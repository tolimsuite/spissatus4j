# Security review: unified encrypt/decrypt entry point

Scope: the unified `Spissatus.encrypt/decrypt` entry, its selection logic, envelope v2 metadata
binding, policy hints, ChaCha key generation, Spring configuration and CLI. Review performed on
branch `feature/unified-encrypt`; no release version was changed.

## Controls implemented in this change

| Area | Control | Verification |
| --- | --- | --- |
| Policy | Selection never calls `PolicyEngine.evaluate`; the crypto service performs exactly one authoritative decision per operation | `UnifiedEntryTest.onePolicyDecisionPerUnifiedOperation`; unified starter integration tests |
| Downgrade | Explicit algorithm/suite has no fallback; policy denial never falls back to another key/algorithm; profiles exclude deprecated/experimental/prohibited and asymmetric algorithms | `AlgorithmSelector`; `UnifiedEntryTest.rejectsUnknownAndProhibitedExplicitAlgorithms` |
| Key isolation | ACTIVE-only for protection, tenant/usage/expiry checks via `peekForUse`; candidate keys are explicitly supplied, never listed | `AlgorithmSelector.keyRejection`; `UnifiedEntryTest`; key module tests |
| Envelope v2 | SHA-256 binding of version, algorithm, key id, creation time, salt/KDF, attributes; domain-separated effective AAD; key version/nonce/ciphertext remain tag-bound | `EnvelopeBindingTest` golden vector; envelope v2 codec tests; `UnifiedEntryTest.rejectsTamperedMetadataBeforeDecryption` |
| v1 legacy | Unified decrypt rejects v1 unless explicitly allowed; freshness checks require v2 | `UnifiedEntryTest.rejectsLegacyV1UnlessExplicitlyAllowed` |
| Error oracle | Tag, padding and ciphertext failures map to one generic `AUTHENTICATION_FAILED` in the unified decrypt path | `DefaultUnifiedCryptoService.secureDecryptFailure`; tamper tests |
| Nonce | Random nonce generated by the crypto service before encryption; detector failure is fail-closed | Existing nonce tests; `UnifiedEntryTest` |
| FIPS/GM | Selector filters by `ComplianceMode` and `fipsCapable` providers; GM profiles require GM algorithms | `UnifiedStarterIntegrationTest.autoSelectionWorksForGmCompliance`; `FipsRuntimeSelectionTest` |
| Audit/metrics | Selection audit contains profile/algorithm/key/count only; metrics tags are bounded (`unknown` for unregistered algorithms) | `UnifiedEntryTest.selectionAuditDoesNotContainAttributeValues`; metric code |
| Capabilities | `fipsAvailable` now reflects installed FIPS-capable providers rather than only the active mode | `DefaultSpissatusTest`/`FipsRuntimeSelectionTest`; code review |
| ChaCha keys | Key manager can generate 256-bit ChaCha20 keys; wrong sizes fail closed | `ChaCha20KeyGenerationTest` |

## Residual and pre-existing risks

These are documented rather than changed because fixing them requires a breaking API or operational
decision.

1. **Key material exposure (high, pre-existing).** `KeyManager` extends `KeyMaterialAccess`, exposing
   `secretKey`, `privateKey` and `publicKey`; `unwrapKey` returns a plaintext DEK. Business code can
   extract key material contrary to the interface contract. Recommendation: move material access to
   an internal SPI, remove public DEK unwrapping, or gate it with an administrative role and audit.
   The unified entry never calls these methods. Deferred to a breaking 0.x change.
2. **Nonce detector scope (medium, pre-existing).** `NonceReuseDetector.register(AlgorithmId, Nonce)`
   has no key id; the default detector is in-memory, TTL/capacity bounded and not shared across
   instances. It is an auxiliary duplicate detector, not a uniqueness guarantee. Deployments should
   use random 96-bit nonces (the facade does) and may provide a persistent detector. Adding key id to
   the SPI is a breaking extension point.
3. **External algorithm metadata (medium, pre-existing).** `AlgorithmCatalog.registerExternal` is a
   public static registration path without module-trust provenance. Trusted modules are still
   anchored by exact class name for `SpissatusModule`, but algorithm metadata registration should be
   moved behind `ModuleContext` or a trust token. Deferred to avoid breaking extension APIs.
4. **Legacy v1 envelopes (accepted).** `encryptToEnvelope` still produces v1 envelopes whose
   `createdAt`/attributes are not authenticated; `decryptEnvelope` accepts them for compatibility.
   New data should use the unified v2 entry. `decryptEnvelope` verifies v2 binding when present.
5. **Auto key listing not implemented.** Unified encryption requires an explicit `keyId` or
   `candidateKeyIds`; listing keys would trigger a second `READ_KEY` policy decision and consume rate
   limits. A non-policy enumeration API is needed before enabling automatic tenant-wide key choice.
6. **Provider substitution.** The low-level crypto service may substitute another provider for the
   same algorithm if the preferred provider cannot create an engine. This is not an algorithm
   downgrade and FIPS mode filters non-FIPS providers, but it is not separately audited yet.
7. **Dependency scanning.** CI does not run an OSV/Dependabot-style scan; Spring Boot `4.2.0-RC2` is
   a release candidate. Do not treat the dependency set as vulnerability-free without a scan.
8. **Persistent audit/nonce.** Audit chains and nonce detection are process-local/bounded. Multi-node
   deployments need external persistence.

## Verification

`./gradlew clean build --no-daemon` passes all modules, tests, Javadoc, and the package-name gate.
`./gradlew checkPackageNames` is part of the build. No release version was changed and no branch was
pushed.
